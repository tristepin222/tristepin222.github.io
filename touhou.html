Touhou Adventure

// overview

About the game

Touhou Adventure is a 2D top-down game built solo in Unity, combining bullet-hell combat inspired by the Touhou Project series with life-sim mechanics like farming, crafting, fishing, and NPC quests.

It was released on Steam as a paid title at $4.99. Getting a game on Steam involves going through Valve's review process, setting up a store page, configuring Steamworks, and managing post-release updates and community feedback.

Published on Steam at store.steampowered.com/app/1777980 . Going through the full Steam publishing pipeline as a solo developer was a significant learning experience in product release, store management, and community interaction.

// game systems

What's in the game

  • Bullet-hell combat (Danmaku)
    Enemies fire directional and homing projectile patterns in real time. Players dodge volleys while attacking back. The system uses pooled projectile emitters with configurable angles and cooldowns.
  • Grid-based farming
    Players till soil tiles, plant seeds, and wait for crops to grow through multiple stages. Neighboring tiles are checked to auto-tile plowed patches into cohesive shapes. Farm layouts persist across scenes via serialized save data.
  • Crafting system
    A 2x2 drag-and-drop crafting grid matches ingredient combinations against recipe definitions. Valid combinations instantly produce output items that can be added to the inventory.
  • Branching dialogue and quests
    NPCs follow daily schedules using a timetable system and A* pathfinding, moving between points on a map based on the in-game hour. Talking to them triggers localized branching conversations with tracked quest objectives.
  • Save and load system
    Player state, inventory contents, farm tile layouts, and dialogue progress are serialized to a binary file. The game fully restores the world on load, including which crops are planted and which quests are active.
  • Character customization
    Players choose from multiple visual styles for their character at the start. Hotbar slot selection controls what tool, weapon, or seed is active, tying equipment choice to in-game actions.
// steamworks

Publishing on Steam

Getting a game onto Steam as a solo developer involves more than writing code. It requires setting up a Steamworks developer account, submitting the game through Valve's review process, building a store page with screenshots, a description, and tags, and then handling the release and any follow-up updates.

On the technical side, the game integrates the Steamworks SDK to access platform features: Steam Cloud for syncing save files across machines, the Steam community hub for player reviews and discussions, and the update pipeline for pushing patches after release.

Managing a live product on Steam also means monitoring community feedback, responding to bug reports, and deciding what to patch. That side of releasing a game taught me about the full lifecycle of a shipped product, not just development.

// post-mortem

What I would do differently

This project was my first complete game shipped to a public platform, and the codebase reflects that. Looking back at the code now, there are clear structural issues I would approach differently.

The most significant problem was relying on a central global singleton that held references to almost everything in the game. Systems that should have been independent ended up tightly coupled through this object, making bugs harder to isolate and changes more risky.

The save system also had a fragile design, using parallel arrays to store related data. A single misaligned index would silently corrupt the inventory on load. Using structured data formats like JSON with named fields from the start would have prevented this class of bug entirely.

The full technical analysis of what went wrong, with code examples and specific bug breakdowns, is documented in the repository README .
